# ADR-006: Tiered Context & OpenViking Compatibility (P2)

## Status
**Proposed (P2 Target)**

## Context
While the OKF Markdown files in `wiki/` provide an ideal, human-readable format for Git version control and static rendering, downstream AI agents frequently need **hierarchical context retrieval** at varying levels of granularity:
1. **L0 (Summary)**: 50-token executive summary for fast intent routing.
2. **L1 (Outline / Structural)**: Section headers, key terms, and cross-topic dependencies for medium-depth reasoning.
3. **L2 (Full Deep Dive)**: Complete specifications, schemas, code examples, and historical meeting notes.

Standard vector search flattens documents into arbitrary token chunks, losing hierarchical relationships. Projects like [`volcengine/OpenViking`](https://github.com/volcengine/OpenViking) provide a filesystem-paradigm context database specifically engineered for tiered L0/L1/L2 agent recall.

## Decision
We design the **`aaif-wiki`** concept schema to be **natively compile-compatible with OpenViking (P2 Milestone)**.

```
       ┌───────────────────────────────────────────────────────────┐
       │             Canonical OKF v0.2 Knowledge Bundle           │
       │                   (/wiki/*.md in Git)                     │
       └─────────────────────────────┬─────────────────────────────┘
                                     │
                                     ▼ (OpenViking Compiler / P2)
       ┌───────────────────────────────────────────────────────────┐
       │               OpenViking Tiered Context Store             │
       ├───────────────────────────────────────────────────────────┤
       │ • L0 (Summary)  ◄── Frontmatter `description` + `# Overview│
       │ • L1 (Outline)  ◄── AST Headings + `related_topics` graph │
       │ • L2 (Full Doc) ◄── Full Markdown body + schema tables    │
       └───────────────────────────────────────────────────────────┘
```

### Technical Mapping to OpenViking
| OpenViking Layer | OKF v0.2 Source Mapping | Agent Use Case |
| :--- | :--- | :--- |
| **L0 (Concept Summary)** | Frontmatter `description` + first paragraph of `# Overview` | Quick intent routing & triage. |
| **L1 (Structural Outline)** | Markdown AST H2/H3 headers + `related_topics` graph edges | Agent architectural planning & dependency mapping. |
| **L2 (Complete Asset)** | Full Markdown document including `# Schema` & `# Examples` | Detailed code generation, RFC reviews, and implementation. |

### Implementation Roadmap (Phase 2)
1. In Phase 1, ensure all OKF concept documents generated by `aaif-wiki` strictly adhere to the H1/H2/H3 hierarchy and frontmatter descriptions required for deterministic L0/L1/L2 extraction.
2. In Phase 2, implement `exporters/openviking_exporter.py` to compile `wiki/` into OpenViking’s native directory structure and vector indices.

## Consequences

### Positive
* **Token-Efficient Agent Recall**: Future agents querying AAIF knowledge can load L0/L1 context first, pulling L2 full documents only when necessary.
* **Dual Serving**: The same knowledge base serves human readers via GitHub/Obsidian and AI agents via OpenViking.

### Negative / Trade-offs
* **Phase 2 Scope**: Requires adding `openviking` dependencies and vector generation steps in Phase 2.
