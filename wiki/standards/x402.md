# Overview
x402 is an open internet-native payment protocol stewarded by the x402 Foundation (Linux Foundation) [^evt-ext-frmoretto-agentic-standards-map-85d122-file-f2b1095b539d-6150b085]. It establishes a standardized mechanism for automated machine-to-machine and AI agent payments directly over HTTP using status 402 challenge-response headers [^evt-ext-frmoretto-agentic-standards-map-85d122-file-f2b1095b539d-6150b085].

Within the broader ecosystem, x402 addresses agent payment settlement alongside standards tracked by the AAIF Agentic Commerce Working Group (`../working-groups/agentic-commerce.md`), including IETF HTTP payment authentication (`../standards/ietf-httpauth-payment.md`), the Agentic Commerce Protocol (`../standards/agentic-commerce-protocol.md`), and Verifiable Intent (`../standards/verifiable-intent.md`).

# Architecture / Specification
x402 defines a wire protocol executed over HTTP [^evt-ext-frmoretto-agentic-standards-map-85d122-file-f2b1095b539d-6150b085]:
- **Payment Challenge**: When requesting a paywalled resource without settlement, the server returns HTTP `402 Payment Required` containing a `PAYMENT-REQUIRED` response header defining acceptable payment terms [^evt-ext-frmoretto-agentic-standards-map-85d122-file-f2b1095b539d-6150b085].
- **Payment Signature**: The client agent re-executes the request supplying a `PAYMENT-SIGNATURE` header meeting the requested payment parameters [^evt-ext-frmoretto-agentic-standards-map-85d122-file-f2b1095b539d-6150b085].
- **Agent Authentication**: An `http-message-signatures` extension cryptographically signs HTTP request components to identify the paying agent [^evt-ext-frmoretto-agentic-standards-map-85d122-file-f2b1095b539d-6150b085].
- **Offer and Receipt**: The `offer-and-receipt` extension allows the server to cryptographically commit to payment terms specified in `accepts[]` (binding payment terms rather than commercial sales conditions) and return a signed receipt upon completion [^evt-ext-frmoretto-agentic-standards-map-85d122-file-f2b1095b539d-6150b085].
- **Settlement Boundary**: The base protocol operates as an irreversible push payment scheme upon execution; fiat settlement rails and credit card deposits remain outside the native protocol layer [^evt-ext-frmoretto-agentic-standards-map-85d122-file-f2b1095b539d-6150b085].
